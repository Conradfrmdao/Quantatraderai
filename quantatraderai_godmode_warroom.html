MetaTrader 4 / 5 integration — three paths

Option 1 — MetaAPI (recommended)easiest
Cloud-based MT4/MT5 REST + WebSocket API. Works on Linux/Mac/Windows. No EA coding required. Supports streaming quotes, order placement, account data.
pip install metaapi-cloud-sdk from metaapi_cloud_sdk import MetaApi api = MetaApi(token='YOUR_METAAPI_TOKEN') account = await api.metatrader_account_api\ .get_account('YOUR_ACCOUNT_ID') connection = account.get_rpc_connection() await connection.connect() # Get balance info = await connection.get_account_information() equity = info['equity'] # Place order (same interface as CCXT adapter) result = await connection.create_market_buy_order( 'EURUSD', 0.1, sl=1.0800, tp=1.1050)
Cost: ~$30/mo production. Free tier for dev. Supports 600+ brokers, MT4 + MT5.
Option 2 — DWX Connect (free/self-hosted)open source
Open-source bridge: MQL4/5 Expert Advisor on the MT side + ZeroMQ Python subscriber. Self-hosted, no cloud dependency, free forever.
pip install pyzmq dwx-connect from api.dwx_client import dwx_client dwx = dwx_client( _broker='ICMarkets-Live', _port=32768 ) # Receives real-time tick data # Places orders via ZeroMQ messages # Requires EA installed on MT4/MT5
Best for: traders with a specific broker. Requires Windows MT4/MT5 instance running. More setup but zero recurring cost.
Option 3 — MT5 native Python (Windows-only)limited
MetaQuotes' official Python package. Direct C++ bindings. Fastest execution but requires MT5 installed on the same Windows machine — breaks your Linux server setup.
pip install MetaTrader5 # Windows only import MetaTrader5 as mt5 mt5.initialize() mt5.login(12345678, password='...', server='ICMarkets-Live') info = mt5.account_info() request = { "action": mt5.TRADE_ACTION_DEAL, "symbol": "EURUSD", "volume": 0.1, "type": mt5.ORDER_TYPE_BUY, "sl": 1.0800, "tp": 1.1050, "comment": "QuantatraderAI" } result = mt5.order_send(request)

Technical debt + architecture upgrades

KMS
Shared ENCRYPTION_KEY — single point of failure
Both Next.js and Python share one key in .env files. If either leaks, every user's API credentials are compromised.
→ Migrate to AWS KMS or Supabase Vault. Separate keys per user, rotatable on demand.
critical
WS
Browser WebSocket has no auth
Any client can connect to ws://localhost:8001 and receive all trade decisions and account data.
→ Add JWT validation on WebSocket handshake. Validate Clerk token on ws:// upgrade request.
critical
DB
psycopg2 sync calls in async FastAPI
Synchronous database calls block the entire event loop. Under load, all WebSocket updates freeze until DB responds.
→ Replace with asyncpg or encode/databases. Async DB = 10× throughput under real user load.
high
WS
No WebSocket reconnect (Binance 24h limit)
Binance forcibly closes streams every 24 hours. Python side has no reconnect logic — agent silently stops receiving data.
→ Exponential backoff reconnect loop. Max 5 retries. Alert user via Telegram on reconnect failure.
high
LOG
Decisions feed unbounded in memory
AI decisions array grows forever in Python memory. After 12+ hours, process memory balloons until crash.
→ Cap in-memory buffer at 100 entries. Persist all to Supabase decisions table asynchronously.
high
TEST
Zero test suite
No pytest. No regression detection. A RiskManager bug or IndicatorEngine error is invisible until it costs real money.
→ pytest for RiskManager (validate every edge case), IndicatorEngine (known OHLCV → known RSI), VenueAdapter mocks.
medium
CDN
No CDN / edge caching
All requests hit origin. Under 1000+ concurrent users, API routes will be slow. Static assets not edge-cached.
→ Vercel Edge for Next.js (already built-in). CloudFront or Cloudflare for Python API. Redis for indicator cache.
medium
OBS
No observability
No Sentry, no structured logging, no Prometheus metrics. When the agent crashes at 3am, you'll never know why.
→ Sentry (Next.js + Python). Structured JSON logs. Prometheus + Grafana for agent latency, tick time, LLM response time.
medium
